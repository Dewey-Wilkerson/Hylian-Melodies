# Decisions

One line each, newest last. Format: date, decision, reason.

- 2026-11-12: Target game version **1.4.0** (the update on the user's cartridge); no separate update file. Reason: RECON.md section 1.
- 2026-11-12: Build on **LASRecomp** (MIT) for lifter and runtime; totk-pc-recomp's shape for installer and packaging. Reason: RECON.md section 7.
- 2026-11-12: Keep the existing git history (LAS Recomp import `9c20fa2`) instead of re-initialising; M1 removes the imported tree and re-adds adapted pieces with attribution. Reason: preserves provenance of the MIT code we adapt.
- 2026-11-12: Removed LAS Recomp's `.github/workflows` (CI and release for its own project). Reason: no remote, nothing is published.
- 2026-11-12: No Unicorn (GPL-2.0) anywhere, not even in tests; jump tables are resolved by our own static pass. Reason: brief 2.4.
- 2026-11-12: Kernel write tracking (soft-dirty / PAGEMAP_SCAN, kernel >= 6.7) is **not** used; no kernel minimum. Reason: small 2D game, LASRecomp's Vulkan path works without it.
- 2026-11-12: Lift `main` and `sdk` only; replace `subsdk0` (movie) and `subsdk1` (glslc) at the API level; drop `rtld`. Reason: RECON.md sections 3 and 6.
- 2026-11-12: Audio through `audout` -> SDL3 audio stream, no audio renderer emulation. Reason: the game's FMOD uses AudioOut.
- 2026-11-12: Network is always "unavailable" (nifm reports no connection, sockets fail). Reason: personal offline use; no online features needed.
- 2026-11-12: hactool runs with explicit `-k`, `--disablekeywarns --suppresskeys`, filtered output, and `HOME` set to a private 0700 temp dir (so it never reads the user's `~/.switch`). Title keys from the cart's ticket go into a 0600 `title.keys` in that temp home, deleted right after, never on the command line or in logs. Reason: hactool prints key values in warnings; command lines are visible in `ps`.
- 2026-11-12: The project's own code is MIT. Reason: brief 2.4 default.
- 2026-11-12: Tests use the standard library `unittest` (pytest is not installed). Reason: fewer dependencies.
- 2026-11-12: A resolved jump table's switch lists only its targets and calls `rt_jt_miss` (fatal) otherwise; the all-instruction-label fallback stays only for unresolved computed branches. Reason: a 50k-instruction function in `main` with 17 tables made clang use 19 GB under the all-label scheme.
- 2026-11-12: Game code is linked statically into one executable (not LAS's separate game library). Reason: one binary to copy per user (brief 8.1), no loader for a game library needed.
- 2026-11-12: Launcher and pacman hooks written early (during M3) because they are independent of the game; M9 still owns the PKGBUILD and the package build. Reason: used compile wait time.
- 2026-11-13: Save mounts journal file creation too: a `CreateFile` leaves `<file>.new` until the next commit; a mount rolls back files that still have one. Reason: a killed run left a committed-looking zero-filled save that crashed the next boot (the Switch rolls uncommitted creates back).
- 2026-11-13: Headless renderer = NVN front end + `runtime/nvn/null_backend.c` (records, never draws); M5 swaps in the Vulkan backend. Reason: lets M4 run the engine's init without a GPU path.
- 2026-11-13: Input is answered at the `nn::hid` function level (LAS Recomp's approach), and the controller-support applet returns "player 1" at once. Reason: the game blocks in that applet when no controller is reported.
- 2026-11-13: Side study: delivering CoH as a Crypt of the NecroDancer (Synchrony) mod is not worth it, neither as the route nor as a side project (docs/NECRODANCER-MOD-FEASIBILITY.md). Reason: a mod is a full logic rewrite on a run-based host engine; the port already lifts, links and boots.
- 2026-11-13: The movie HLE answers end of stream with status `0x2000` (default; `HM_MOVIE_EOS_CODE` overrides). Reason: the game compares the extractor's result with that value; anything else made it wait forever on the splash video.
- 2026-11-13: M5 renderer = LAS Recomp's Vulkan backend + Maxwell translator. Its Link's Awakening features (recolouring, texture patches, widescreen camera, randomizer pots, warps) are answered "off" by `runtime/nvn/las_feature_stubs.c`; its shipped shader list is empty; SMAA is not built (its lookup tables are large data headers); the overlay menu is a stand-in until M10. Reason: get this game's frames on screen first, trim later.
- 2026-11-13: Removed from the restored code everything keyed to Link's Awakening's own shader words or hashes (the translator's light-tile fix, a pot draw check). Reason: another game's code bytes, no use here (CONTRIBUTING content rules).
- 2026-11-13: LAS Recomp's forced 30 fps fallback is disabled (it wrote into Link's Awakening's game data). Reason: a rhythm game must stay at 60.
- 2026-11-13: TLD4 (texture gather) added to the translator; per-texel offsets become four gathers on coordinates moved by offset / size. Reason: the game's title-screen effects use it; GLSL needs constant offsets otherwise.
- 2026-11-13: The movie decoder writes into the output buffer the game passes (its video textures' memory) and raises "output format changed" once per decoder. Reason: without them the splash videos were green and the second one stalled the game for 5 s (it waits for both decoders to start).
- 2026-11-13: `tools/build_game.py` builds `game` (Vulkan + SDL3 window -> `hylian-melodies`) and `headless` (null backend -> `hylian-melodies-headless`); `HM_RUN_SECONDS`, `HM_DUMP_AT`, `HM_WINDOW_SHOT=a,b,...` support test runs.
- 2026-11-13: Audio output keeps the sound card as the clock (LAS Recomp's design) but holds far less: device period 256 frames asked of the server (`audio_period`), our stream released at one period (`audio_queue_ms`). Reason: our share of the latency fell from ~64-85 ms to ~11-32 ms with no gaps in a 10-minute run; the game's own 2-3 queued buffers absorb late wake-ups.
- 2026-11-13: Input is event-driven state in atomics, read by the game's `GetNpadState` HLE whenever it polls (no queue). Gamepad buttons map by position like the Switch (A = right face button); the keyboard is a complete alternative; both are rebindable in the ini. Reason: lowest latency for a rhythm game, and the game's own button prompts are Nintendo's.
- 2026-11-13: 3D textures: a block holds at most 16 GOBs, so a deep block gets a shorter height (`runtime/nvn/tegra.c`). Reason: the game's 16x16x16 colour-grading LUT (used underground) is only smooth with 1 x 16 GOBs; LAS Recomp's 2D rule (2 x 16) scrambled it into purple/yellow casts. One texture's evidence; `HM_DUMP_3D=1` dumps 3D textures to check new ones.
- 2026-11-13: Lifter: FP/SIMD destinations are not GPRs when looking for jump tables, and the bounds-check search spans 32 instructions. Reason: a switch with FP work between the table load and `br x8` was missed and crashed the game.
- 2026-11-13: Render at native scale by default (`resolution = 1`) and present with "sharp bilinear" (`upscale_filter = 0`). Reason: LAS Recomp's "match the window" mode scaled the game's targets relative to a 1920x1080 screen (0.9667 in a 1856x1044 window), which put flickering seams between tiles and blurred text; confirmed by the owner, both gone at native scale.
- 2026-11-13 (owner): the package covers the XCI route only for now (base + 1.4.0 + four DLC in one cartridge dump); NSP inputs later. No firmware input (the game uses its own fonts). No build-time shader step (few shaders; compiled on first use and cached per user), so `makepkg` needs no graphical session.
- 2026-11-13 (owner): game installed globally in `/opt/hylian-melodies` (self-contained, architecture-specific: the FHS place for it; the brief's `/usr/share` was the owner's intent, `/opt` chosen as more correct), support files in `/usr/share/hylian-melodies-recomp`, launcher `/usr/bin/hylian-melodies`; user data per XDG in `${XDG_DATA_HOME:-~/.local/share}/hylian-melodies`.
- 2026-11-13 (owner): `--fullscreen` (borderless at the desktop's resolution) and `--windowed` command-line flags until there is a settings UI; the ini's `fullscreen = 1` also works.
- 2026-11-13: Frame pacing: each present waits for a steady 60 Hz cadence (x the present interval) on the monotonic clock, like the Switch's display (`frame_pacing`, default on). Reason: the game never waits on the vsync event; with presents that return at once its own limiter ran it at 61.07 fps (1.8 % fast). Now 60.0 fps, frame times at most 17-18 ms.
- 2026-11-14: The overlay menu opens with F1 or Minus+Plus (or Home), not Esc: Esc is the game's + on the keyboard. Settings are saved when it closes, changed keys only, in place in the player's ini.
- 2026-11-14 (owner): the menu draws all its text with the game's own large serif display face (BFFNT, 42-pixel line, small capitals for lowercase), read at run time from the player's RomFS (our own reader, `runtime/ui/game_font.c`; picked by line height and ASCII coverage, never by file name), scaled to the window with filtering (owner: best looking at high resolutions), heading 1.5x; system font as fallback. (A first version used the 16-pixel pixel font at whole-number scales.)
- 2026-11-14: The setup records a hash of each step's project sources and redoes lift/compile (and everything after) when it changed. Reason: `makepkg -f` after code changes resumed with "compile already done" and packaged the old executable.
- 2026-11-14 (owner): every build is generic by default: `tools/build_game.py`, the setup (`--march`) and the PKGBUILD (`HM_MARCH`) compile for x86-64-v2; v3 or native is the opt-in "optimize for this computer's CPU" (v3 refused on a CPU without it). The CPU level is part of the compile step's source hash, so changing it compiles again. The runtime checks the level it was built for at start. v2 vs v3 measured (owner's OK): the game's own work per frame is the same, median 1.06-1.09 ms (v2) vs 1.10-1.12 ms (v3) on the dev machine, so v2 costs nothing measurable here.
- 2026-11-14 (owner): history rewritten without the LAS Recomp import commit (it held Link's Awakening data) and with the pseudonym "Bagu" <bagu@hylian-melodies.invalid>; replaces the 2026-11-12 "keep the existing history" decision. Provenance stays in THIRD_PARTY_NOTICES.md and the owner's local backup bundle.
- 2026-11-14: The frame pacer counts a frame shown late as "doesn't fit 60" only when the frame's work plus its waits for the GPU and the present take more than its vsyncs; a frame late because the game itself waited (its own 30 fps mode) doesn't count. Reason: holding for those reported 20 ms GPU counters to a game with ~1 ms frames. The display cadence's wait counts as idle time.
